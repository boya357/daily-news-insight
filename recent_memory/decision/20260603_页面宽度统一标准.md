# 页面宽度统一标准决策（2026-06-03）

## 背景
用户询问所有页面的容器宽度是否应该统一，是按MLCC报告的大小还是首页的大小合适。

## 分析过程
1. 导航栏容器：模板和首页均已统一为 `max-w-5xl`，无需修改
2. 内容容器差异：
   - 报告页模板：`max-w-4xl`（更窄，长文本阅读体验更好，符合MLCC标准）
   - 首页：`max-w-6xl`（更宽，适合展示卡片列表）
   - 列表页：原有宽度不统一（多数为`max-w-5xl`，部分为`max-w-4xl`/`max-w-7xl`）
3. z-index差异：导航栏HTML存在内联`z-index: 999999 !important`，与CSS类的统一控制冲突

## 决策结论
采用差异化宽度策略，兼顾阅读体验与展示需求：
- 导航栏宽度：所有页面统一`max-w-5xl`（已统一）
- 列表页/首页内容宽度：统一`max-w-6xl`（卡片展示需要更宽空间）
- 报告内容页宽度：保留`max-w-4xl`（MLCC标准，阅读体验最佳）
- level1深度研报宽度：保留`max-w-7xl`（复杂图表展示需求）
- z-index：删除所有HTML内联样式，统一由`.glass-nav` CSS类控制

## 执行结果
1. 清理了11个页面的导航栏多余内联z-index样式，全部统一为标准格式
2. 将10个列表页的内容容器宽度统一修改为`max-w-6xl`
3. 验证所有页面符合统一标准
4. 提交Git并推送到GitHub，提交信息：`统一页面宽度 - 导航栏max-w-5xl / 列表页内容max-w-6xl / 报告内容max-w-4xl`

## 影响范围
- 修改文件：`docs/index.html` + 10个模块的`latest.html`列表页
- 不修改：报告模板文件（已符合`max-w-4xl`标准）、level1深度研报模板（保留`max-w-7xl`）
