# Git合并冲突事故复盘（2026-06-15）

## 事故概述
**时间**：2026年6月15日
**严重等级**：严重（全站页面混乱）
**影响范围**：363个HTML文件残留Git冲突标记

## 事故经过
1. **起因：气泡卡片V2.0升级后，本地有变更需要推送到远程
2. **操作**：执行 `git pull origin main` 超时，改用 `git merge origin/main -X theirs`
3. **问题**：合并完成后直接提交并推送，未检查合并结果
4. **现象**：用户反馈页面彻底混乱，显示 `<<<<<<< HEAD`、`=======`、`>>>>>>>` 等Git冲突标记
5. **影响**：网站所有页面都可能出现问题，用户体验严重受损

## 根本原因
1. `-X theirs` 策略未能正确处理所有冲突，尤其是大量HTML文件中留下了冲突标记
2. 合并后未进行任何检查就直接推送
3. 没有在推送前验证页面有效性的环节

## 恢复过程
1. 发现问题后立即执行 `git reset --hard 86a297a` 回退到合并前的正常版本
2. 执行 `git push -f origin main` 强制推送到远程，恢复网站正常
3. 确认GitHub Pages重新部署后，网站恢复正常

## 修复的问题
本次事故同时暴露和修复了另一个bug：**操作建议字典渲染问题**

### 操作建议字典渲染bug
- **现象**：持仓卡片中操作建议字段显示原始Python字典代码
- **原因**：`advice` 字段是dict类型（包含type、type_label、color、text），但模板中直接当字符串渲染
- **修复**：在 `daily.py` 和 `daily_pro.py` 中新增 `_render_advice()` 方法，自动检测类型并分别渲染
- **受影响页面**：4个（今日日报、昨日日报、测试页、持仓监控页）

## 教训与改进措施

### 立即执行
1. **推送前强制检查**：git push前必须抽查至少2-3个关键页面，确认没有问题
2. **合并后验证**：任何merge/rebase操作后，必须检查文件内容是否正常

### 长期改进
1. 建立CI/CD校验流程，自动检测HTML中的冲突标记
2. 完善 `validate_system.sh` 脚本，增加冲突标记检测
3. Git钩子中增加冲突标记检查，禁止提交包含 `<<<<<<<` 的文件

## 关键命令记录
- 回退到指定提交：`git reset --hard <commit_hash>`
- 强制推送：`git push -f origin main`
- 检查冲突标记：`grep -rl "<<<<<<<" docs/ | wc -l`
