# 工作流监控页面白卡白字问题修复（2026-06-14）

## 问题描述
用户反馈工作流监控页面"白卡白字"，即白色卡片背景上显示白色文字，完全看不清内容，刷新后问题依旧。

## 根本原因
CSS样式优先级冲突：
- 页面头部style标签定义了深紫色卡片背景
- 页面底部独立style标签重新定义了`.card-glass { background: rgba(255,255,255,0.95); }`
- 由于CSS层叠规则，后面的白色背景样式覆盖了前面的深紫色样式
- 最终导致：白色卡片 + 白色文字 = 完全不可读

## 排查要点
1. 首次检查顶部style看似正常，容易误判
2. 用户反馈"刷新还是白卡白字"是典型信号
3. 必须用`grep -n ".card-glass"`检查所有style标签
4. 更新日志页面（changelog.html）也存在同样问题

## 解决方案对比
- 方案A：直接改静态HTML白色背景，快但治标不治本
- 方案B：改为Pro生成器生成，从根源解决，统一架构

## 最终决策
采用**方案B为主，方案A为辅**：
1. 先修复现有静态页面（临时方案）
2. 开发`workflow_status_pro.py`Pro生成器
3. 用Pro生成器重新生成页面，彻底解决问题

## 修复成果
- ✅ 工作流监控页面：从静态HTML改为Pro生成器，彻底解决白卡白字
- ✅ 更新日志页面：同步修复白色背景问题
- ✅ 新增workflow_status_pro.py生成器

## 经验教训
1. **CSS优先级陷阱**：后面的style标签会覆盖前面的，修改样式必须检查所有定义
2. **静态页面维护风险**：多个分散的style标签极易导致样式冲突
3. **统一架构价值**：Pro生成器从根源避免此类问题，样式由基类统一管理
4. **用户反馈识别**："白卡白字"、"刷新还是老样子"是CSS覆盖的典型信号

## 预防措施
1. 新页面优先使用Pro生成器创建
2. 静态页面改CSS前必须`grep -n ".card-glass"`检查所有定义
3. 逐步将旧版静态页面迁移到Pro架构
