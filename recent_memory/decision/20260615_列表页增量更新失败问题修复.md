# 列表页增量更新失败问题修复

**日期**：2026-06-15
**分类**：问题修复 / 决策记录
**状态**：已修复

## 问题描述

### 用户反馈
- "电脑端没有添加到S级催化扫描列表页"
- "移动端覆盖了列表页"

### 实际问题
1. **S级催化扫描频道**：新生成的盘后S级催化报告没有正确添加到列表页中
2. **产业链总览频道**：ReportPublisher发布利基型存储报告时，列表页自动更新失败
3. 用户看到的"覆盖"现象实际上是：增量更新失败后，列表页保持原样，用户误以为被覆盖了

## 根本原因

### 技术层面
- 部分频道的`latest.html`列表页是早期静态页面，没有包含`LIST_START_MARKER`和`LIST_END_MARKER`注释标记
- ListPageGenerator的增量插入逻辑依赖这些标记来定位插入位置
- 没有标记的情况下，兼容模式查找`report-card`类也失败（因为老页面使用不同的CSS类名）
- 最终导致增量更新静默失败，新报告没有出现在列表中

### 涉及频道
- S级催化扫描（`docs/s级催化扫描/latest.html`）
- 产业链总览（`docs/industry_chain/latest.html`）
- 其他未迁移到Pro架构的列表页可能也有同样问题

## 修复方案

### 临时修复（已执行）
1. **S级催化扫描列表页**：使用`ListPageProGenerator.generate_all_list_pages()`重新生成完整列表页
   - 重新生成后包含24份报告
   - 最新报告按时间倒序排列在最前面
   
2. **产业链总览列表页**：使用Python脚本手动在grid容器后插入新报告卡片
   - 直接操作HTML DOM，在第一个卡片前插入新卡片
   - 确保新报告出现在列表最顶部

### 长期修复方案（待执行）
1. 将所有列表页统一迁移到Pro生成器架构
2. 所有列表页统一使用标准的LIST_START/LIST_END标记
3. 确保ListPageGenerator和ReportPublisher的增量更新在所有频道正常工作
4. 添加增量更新后的校验：检查新报告标题是否在列表页中

## 教训总结

1. **不要假设所有页面都有统一标记**：历史遗留页面可能使用不同的格式
2. **增量更新后必须验证**：不能只看返回成功，要实际检查新内容是否在页面中
3. **统一架构是根本解决方案**：Pro生成器架构可以从根源避免这类格式不统一问题
4. **用户反馈要认真对待**："电脑端没有、移动端覆盖"的描述虽然不准确，但反映了实际问题
