### ❌ 错误001：非交易日生成错误数据

**发生时间**：2026-04-25
**发现方式**：用户质询"这是什么内容，哪天的数据啊，弄错了吧"

**问题描述**：
- 周六（非交易日）执行盘后速递任务
- 使用2026-03-23的历史模板数据，而非当日真实行情

1. `generate_aftermarket_report.py`未检查交易日
2. 脚本使用硬编码模板数据，未集成实时行情API
3. 无交易日判断逻辑

**影响范围**：
- 盘后速递报告数据错误
- 用户信任受损

**修复方案**：
1. 新增`is_trading_day()`函数，检查指定日期是否为交易日
2. `main()`函数开头添加交易日判断，非交易日自动退出
3. 添加`--force`参数支持强制执行（调试用）
4. 输出清晰提示："周六（2026-04-25）非交易日"

**代码修改**：
- 文件：`./长期计划/信息分析洞察计划/src/generate_aftermarket_report.py`
- 新增44行交易日检查代码
- 修改main()函数添加交易日判断

**测试验证**：
```
执行结果：
⏭️  跳过执行：周六（2026-04-25）非交易日
   周末/节假日不生成盘后速递报告
```

**预防措施**：
1. 所有定时任务执行前检查是否为交易日
2. 数据源必须是实时API，禁止硬编码模板
3. 生成报告前验证数据时效性

**后续改进**：
- 待办：集成实时行情API（akshare/tushare/东方财富接口）
- 待办：删除所有硬编码模板数据

### ❌ 错误006：推理能力不足，只会"补漏"而非"推导"

**发生时间**：2026-04-25
**发现方式**：用户指出复盘逻辑问题

**问题描述**：
- 系统复盘只关注"遗漏了个股、遗漏了题材"
- 缺乏从题材到个股的**逻辑推导能力**
- 不会举一反三，不会深度分析

**用户举例**：
- 发现"涨价"题材 → 应该推导涨价逻辑带来的利好
- 分析能否影响股市中的哪些个股
- 深度挖掘分析并推理
- 结合网络上别人的理解

**根本原因**：
1. 复盘思维停留在"覆盖面"，而非"推理链"
2. 缺少从题材→影响→个股的推导模型
3. 没有整合网络观点、市场共识的能力
4. 算法是"关键词匹配"，不是"逻辑推理"

**正确做法**：
当一个题材出现时，应该：
1. **分析题材本质**：是什么驱动？政策？供需？事件？
2. **推导影响链条**：上游→中游→下游，谁受益？谁受损？
3. **量化影响程度**：弹性多大？时间维度？
4. **定位相关个股**：哪些公司直接受益？间接受益？
5. **结合市场视角**：资金怎么看？情绪如何？技术面位置？
6. **整合外部观点**：分析师怎么说？网络共识是什么？

**改进方向**：
- 复盘不只是"补漏"，要分析"为什么遗漏"
- 建立题材→影响的推理模型
- 搜索整合市场观点
- 用逻辑而非关键词来找个股

**状态**：⚠️ 待改进（核心能力提升，非简单修复）

## 2026-04-28 GitHub Pages中文路径问题

### 问题描述
- 推送链接指向首页目录，而非具体报告文件
- 报告文件名包含中文字符，GitHub Pages返回"Bad request"
- 用户点击链接看不到具体报告内容

### 根本原因
1. GitHub Pages不支持URL中的中文字符
2. 推送脚本生成链接逻辑有误，只推送首页而非具体文件
3. 文件命名规范缺失

### 修复措施
1. 文件命名规范：报告文件统一使用英文/数字格式
   - 每日新闻洞察：`daily_insight_YYYYMMDD.md`
   - 盘中快报：`midday_report_YYYYMMDD.md`
   - 盘后速递：`aftermarket_report_YYYYMMDD.md`
2. 目录命名规范：统一使用英文路径
   - `outputs/daily_insight/`
   - `outputs/midday_report/`
   - `outputs/aftermarket_report/`
3. 推送链接修复：必须指向具体文件而非首页

### 长期规范
- 所有推送链接必须验证可访问
- 文件名和目录名禁用中文
- 推送前测试GitHub Pages链接

### 企业微信推送格式规范

**推送流程（已验证可用）**：
1. **摘要**：从markdown报告提取核心内容，用markdown类型推送
2. **报告转HTML**：把markdown报告复制到docs目录，GitHub Pages自动渲染成HTML
3. **链接卡片**：用**news消息类型**推送，显示图文卡片，点击即可跳转

**文件路径规范**：
- Markdown源文件：`outputs/daily_insight/daily_insight_YYYYMMDD.md`
- HTML渲染文件：`docs/daily/YYYYMMDD.md` + `docs/daily_latest.md`
- HTML访问链接：`https://boya357.github.io/daily-news-insight/daily_latest.html`

**news消息示例**：
```json
{
  "msgtype": "news",
  "news": {
    "articles": [{
      "title": "📊 每日新闻洞察报告 | YYYY年MM月DD日",
      "description": "摘要内容...",
      "url": "https://boya357.github.io/daily-news-insight/daily_latest.html"
    }]
  }
}
```

**重要发现**：
- 企业微信Markdown消息**不支持链接格式**（`[text](url)` 和 `<url|text>` 都不行）
- 企业微信Text消息也不支持链接格式
- **正确方式**：用**news消息类型**，显示图文卡片，点击即可跳转
